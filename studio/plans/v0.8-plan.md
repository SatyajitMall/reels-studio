## 2. Changes, in three batches

Each line gives: the evidence → the owner file → the size (S / M / L).

### Batch A: picture quality + gate economics (biggest impact, mostly rule edits). **Done, v0.8.0**

1. **Camera-relative grading is the default.** Each shot is checked against its camera file at the same framing:
   - luma at or slightly above the camera's, lifted only until any channel at 255 (beyond light sources) reaches 2 % of the frame;
   - saturation within ±5 % and hue within ±3° of the camera;
   - crushed no worse than the camera's own;
   - whites never pulled below the camera unless they clip.

   No creative look and no Hue vs Sat by default. A look is allowed only if it beats "camera" on the phone sheet, at ≤ 30 % strength. `muted_red` becomes an option, not story-montage's default.
   → 20 colour rounds, 36 majors, 4 reels; gd #36/#37, pk-correction-stacking.
   → CLAUDE.md §2.5 + §3 V3 row, effects-playbook §A, the 3 playbooks' Colour lines, SKILL Phase 2/4 (replace "crushed < 25 %"). M.
2. **`scripts/camera_fidelity.py`** (promoted from HQ's `raw_vs_render.py` and goddess `v9_fidelity.py`). It finds each shot's camera frame and framing by matching, then writes the per-shot deltas and a camera | render sheet at phone size and 100 % crop. It runs in Phase 4, the gate and Checkpoint 2. → M.
3. **Framing default: ≥ 80 % of the camera width** (enlargement ≤ 1.25×, Scale ≤ 62.5 on vertical 4K) with gentle pushes (~+6). Exceptions are named in the brief. → uski post-approval round, goddess v2/v8; the CRs' own cap (Scale 75) is the failing value. → effects-playbook §B, SKILL Phase 3. S.
4. **Processing restraint:**
   - grain off on night phone footage, ≤ 5 % otherwise;
   - no extra sharpen;
   - light denoise only where noise shows at phone size (AE route).

   This carries out the director's earlier "make the quality fixes studio defaults". → effects-playbook §A4, cinematic-montage. S.
5. **Delivery:** a ProRes master → x264 High at 16–20 Mb/s (`scripts/encode_master.py`) for `_mix` and `_IG`. `verify_render.py` FAILs Main profile, < 12 Mb/s or yuvj420p (today it passes all three). Review copies go out as a file.
   → uski "very poor on iPhone", goddess 9.2 Mb/s preset. → SKILL Phase 7, `verify_render.py`. M.
6. **Slow motion:**
   - AE Timewarp (Pixel Motion, 4K) is the default for ≤ 30 fps footage; Premiere Optical Flow only on calm shots.
   - Reality-doc rows: on a speed-changed clip, the DOM's in/out are **source ÷ speed**, and Scale keys don't run the full ramp.
   - `ae_roundtrip.py` handles the camera's −90° rotation flag.
   - Slow-mo QA bar (the gate's finding): no frame > 70 % blend; half-res alternation within 0.03 of real.

   → goddess v10 FAIL → v10b PASS, pn2 #29, pujo ghosting ×8. → effects-playbook §C, after-effects.md, reality doc, `ae_roundtrip.py`, reel-reviewer.md. M.
7. **Review-gate economics:**
   - **Unpin Fable.** The reviewer runs on a model other than the editor's: Opus ↔ Fable, Sonnet when the preferred one is out of credits. Today the gate can't run at all.
   - **`scripts/pregate.py`:** scripted hard fails first (verify_render, frame_scan, camera_fidelity, audio). The LLM gate runs only on a clean pregate.
   - **Fix versions get a focused review** of the changed frame ranges only, with a small script that diffs two exports. Goddess already did this. A full blind review is only for a new cut.

   → 59 runs, 47 FAIL, Fable at 100 %. → review-gate.md, reel-reviewer.md (drop `model: fable`), new `pregate.py`. M.
8. **Harness hygiene** (S each):

   - add `frame_scan` to SKILL Phase 7b;

### Batch B: fewer rounds (process)

9. **Offline preview first, one Premiere build at the end.** Promote Pujo's `tools/preview_assemble.py` to **`scripts/preview_edl.py`**. It reads the EDL, decodes each shot from the camera file by frame number, crops to 9:16, ramps the pushes, applies the camera-relative correction approximately, lays on subtitles, title and end card, adds the VO or music, and writes a phone H.264. Its source is already proven: Pujo v6–v10 were built this way while Premiere was busy.
   - **Pace, picks, framing and slow-mo windows are locked on offline previews** (minutes each, no Premiere, no lock contention). Premiere then gets one build for the final grade and finishing.

   - The pregate (item 7) runs on previews too, so cut-level defects (jumps, safe zone, pick-to-line) are caught before Premiere.

## 3. Deliberately not changing
- The HQ / reel split, the track layout, and the three playbooks' structure. Only their colour and grain lines change.
- **No new MCPs** (the AE MCPs stay in the backlog) and **no Graph API posting**. The director taps Share.
- **No Remotion:** it overlaps HyperFrames (code → video), and its licence is free only for individuals and small teams. **No yt-dlp:** Instagram references usually need a login cookie, so they stay as screen recordings or downloads from the director.
- **No baked per-shot look as a default.** `shot_look.py` stays HQ scratch: the director rejected it on the full reel.
- No synthetic bokeh, no force-matching a reference's grade numbers (Pujo's 0.25 read "too dark"), no AE `light_rays`.
- No template `.prproj` yet. Cloning a sequence that already has V3 covers it (uski lead); verify it, then document it in the reality doc.
